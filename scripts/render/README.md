# `render` — the doc-publish engine

The canonical copy of the HTML design-artifact renderer, extracted from rawgentic in wave 0a of
epic #11 (issue #15). It turns a markdown doc into a self-contained, CSP-safe HTML page: inline
CSS only, no external hosts, always stamped.

## Running it

Use the launcher, from anywhere:

```bash
scripts/render-doc --md <in>.md --out <out>.html --title "..." [--style design]
```

`python3 -m render` also works, but only with `cwd` or `PYTHONPATH` pointing at `scripts/`, and it
is **not** collision-safe: Python resolves `-m render` by `sys.path` order, so from an unexpected
directory it can import a different installed package named `render`. That was observed live, not
theorised. `render-doc` pins its own directory and verifies `render.__file__` came from there
before running anything.

## Who owns which module

Wave 0a created every file here. Only `__init__.py` has a body; the rest are deliberate empty
seams, and `test_package_seam.py` fails if one of them quietly grows a declaration.

| module | owner | holds |
|---|---|---|
| `__init__.py` | wave 0a (#15) | the whole engine today — `render_artifact()`, `main()`, `_TEMPLATES` |
| `markdown.py` | wave 1 (#16) | the block/inline parser |
| `blocks.py` | wave 2 (#17) | typed fenced blocks |
| `templates/` | waves 3–4 (#13, #18) | one module per doc type |
| `lint.py` | wave 5 (#12) | contrast, external requests, stamp, secrets |
| `vdl.py` | wave 6 (#14) | per-project token packs |

## Two traps, both load-bearing

**1. Two renderers carry `inline_fn=_inline` as a def-time default.** Both
`_render_body_plain` (`__init__.py:85`) and `_render_roadmap` (`:258`) bind `_inline` when the
function is *defined*, not when it is called.

Scope this precisely, because it is narrower than it first looks: on every **public** render path
`_render_body` builds the inline function fresh and passes it explicitly
(`__init__.py:386-387`), so today's output is unaffected. The stale default only reaches callers
that omit `inline_fn` — direct calls to either renderer, which is what tests and future internal
code do.

That still matters for wave 1. It replaces `_inline` to fix the parser; if it moves the parser
into `markdown.py` and leaves either default bound to the old function, any such caller keeps the
old behaviour while the public path gets the new one — a split that unit tests exercising
`_inline` directly would never reveal. Convert **both** to a call-time lookup
(`inline_fn=None` → resolve inside the body) before changing `_inline`.

**2. Two strings used to say "rawgentic" — FIXED in #24 (2026-08-03).** The footer read
`generated by hooks/render_artifact.py` and the eyebrow read `rawgentic design artifact`. Both
became false when rawgentic#807 deleted that path. They were deliberately left alone in wave 0a
because issue #15's acceptance criterion required rendered output to be byte-identical before and
after the move — changing either meant regenerating the committed exemplar, which is a
golden-output migration.

The footer now reads `generated by design-doc-publish` and the eyebrow reads `design artifact`.
#24 also added a structural `<meta name="generator" content="design-doc-publish">`, so
`deploy_check.py` recognises engine output by markup rather than by display prose — the coupling
that made the old rename a two-file change in the first place.

History kept below because the third occurrence it names is still the kind of thing that is easy
to miss: the golden
markdown source `../../docs/design-language-example.md` names that path in its own body, so
fixing only the two engine strings would leave it baked into the rendered exemplar.

Three further defects were found while landing this engine and confirmed live. All are
pre-existing rawgentic behaviour that the byte-identical copy inherited, so none could be fixed
here: **#21** (`status_chip` has no negation handling — "not done" renders a green DONE chip),
**#22** (a security scan that never ran renders as a clean result), **#23**
(`test_no_external_hosts` is vacuous — an external `<img>` is untested).

## The exemplar contract

`../../docs/design-language-example.md` + `.html` are an immutable pair: the `.md` rendered with
`--style design --generated-at "2026-07-10 12:00 MDT" --title "Design-language exemplar"` must
reproduce the `.html` byte for byte. `test_byte_identity.py` enforces it, and
`test_gate_detects_drift` proves that check can actually fail. Do not regenerate either file
casually — that pair is the only standing evidence that rendered output has not drifted.
