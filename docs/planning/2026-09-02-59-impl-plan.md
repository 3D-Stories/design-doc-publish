- **Test style:** Red-Green-Refactor, because `capabilities.has_tests` is true
- **Risk calibration:** **2 of 10** tasks are `high`, which is 20% and inside the documented

## The shape this repository forces

A style cannot land incrementally. Adding `minutes` to `MODULES` turns **seven** guard files red
at once — the golden SHA oracle, the classification test, the two doc-table pins, the gallery
guard, the currency gate, the rendered-styles guard and the reachability guard.

That is by design. Each guard exists so a style cannot ship with a surface missing. So this is one
red-to-green arc with a scoped verification per task, and the full suite runs once at Step 9.

No task declares a `parallel_group`. Each one depends on the registration from the task before it,
so the whole plan is serial and says so rather than claiming a parallelism it cannot prove.

**Three files are touched by more than one task, and that is intended rather than a conflict.**
`scripts/tests/regen_docs_pages.py` is edited three times (T0's stamp bump, T6's gallery entry,
T9's two planning entries) and `README.md` twice (T4's `--type` row, T6's gallery cell). The
`files` declarations exist so a `parallel_group` can be judged disjoint. Nothing here is parallel,
so the overlap costs nothing — but one writer at a time is still the rule, and the serial order
above is that writer.

## The screenshot recipe, proven rather than assumed

`test_example_gallery.py` requires one PNG per style and nothing in the repository produces them.
This exact command was spiked on 2026-09-02 and reproduced **three** committed PNGs byte for byte —
`design.png` (sha256 `b7914e2f1c8b083025fa6371c900ac22e58c273700f266a5e4fef147a1702362`,
125553 bytes), `review.png` and `slide-deck.png` — on Google Chrome 152.0.7977.64:

```bash
google-chrome --headless --no-sandbox --disable-gpu --hide-scrollbars \
  --force-device-scale-factor=1 --window-size=1280,1000 \
  --screenshot=docs/examples/gallery/minutes.png \
  "file://$PWD/docs/examples/gallery/minutes.html"
```

Every committed gallery PNG is exactly 1280 x 1000, so this is a viewport shot rather than a
full-page one. The Playwright MCP browser was tried first and refused with "Browser is already in
use" — another session holds it. That browser was **not** killed. This route was found instead, and
it is the better one, because reproducing three committed artifacts byte for byte proves the recipe
rather than merely proving a screenshot is possible.

T6 records this command in a comment beside the gallery manifest entry. That is a two-line
addition, and it closes a real gap: the recipe existed only in whoever last ran it.

### What the screenshot assertions do and do not prove

Both review passes raised the same objection and it is fair. Correct dimensions plus a vague
"non-trivial" size do not establish that the PNG depicts the minutes page. A browser error page is
1280 x 1000 too.

**Declined: a reviewed SHA oracle or an image-variance comparison.** That was the recommended
remedy. A screenshot SHA is brittle across font rendering, Chrome versions and GPU flags, so it
would fail for reasons having nothing to do with the page. This repository also carries no
image-comparison dependency to set a tolerance against. A gate that goes red on a Chrome upgrade
teaches people to ignore it.

**Adopted instead, two things, and neither pretends to be the other:**

1. **A byte floor DERIVED from committed data, not invented.** The smallest committed gallery PNG
   is `module-map.png` at 72527 bytes, so the floor is half of that. It is self-maintaining, and
   it catches a blank page, which compresses to a few kilobytes.
2. **A recorded visual inspection.** The captured PNG is opened and looked at, and what was seen
   goes into the session notes: the minutes heading, the ledger strip, and at least the agreed and
   decided regions.

**The automated assertions bound the failure class. The human look is the evidence.** That is
stated plainly because the reverse claim would be the defect: no assertion in this plan proves the
screenshot depicts minutes. The inspection does, once, at the commit that creates it. A later
silent rot of that PNG is NOT caught, and #58 already recorded the same gap for the other fourteen.
